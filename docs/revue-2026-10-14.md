# Revue de My Job Community par rapport à la demande initiale

Revue du 14/10/2026, sur l'état du dépôt à la révision `8a59278` (Strapi 5.57, Astro 7.3, MariaDB 11).

**Méthode.** Lecture du code (cms, site, builder, nginx) en quatre revues parallèles : sécurité, pipeline des offres Gestmax, site public (RGAA, SEO, éco-conception), back-office et modèle de contenu. Les requêtes ont été faites sur la pile Docker locale (API Strapi sur `:1337`, site statique sur `:8080`). Les 26 tests Vitest du site passent (lancés dans le conteneur). `tsc` n'a pas pu tourner pour `cms/`, faute de `node_modules` et en Node 20 local. Aucun fichier du projet n'a été modifié pendant la revue.

**Légende des preuves.**
- **Reproduit** : constaté sur la pile qui tourne.
- **Vérifié dans le code** : confirmé en relisant le code.
- **Lecture seule** : relevé par une revue, non rejoué.
- **À valider** : dépend d'une vraie instance Gestmax.

## 1. Verdict

Le prototype couvre toute la demande, et l'architecture est saine (site statique, API JSON, Strapi découplé de l'Astro par un seul fichier). **Il n'est pas prêt pour la production** : trois failles, une synchronisation sans garde-fou et l'absence de configuration de production sont à corriger avant Laval.

## 3. À corriger avant la mise en production

### 1. Les brouillons sont lisibles par n'importe qui — reproduit

Le correctif annoncé dans `docs/architecture.md` (§3 ter) est inopérant. `cms/src/middlewares/brouillons.ts:10` teste `ctx.path.startsWith('/api/') && ctx.query.status === 'draft'`.

| Requête | Résultat |
|---|---|
| `/api/pages?status=draft` | 403 (bloqué) |
| `/Api/pages?status=draft` | 200, 5 pages avec `publishedAt: null` |
| `/api/pages?status[0]=draft` | 200, 5 pages avec `publishedAt: null` |

Le routeur ne tient pas compte de la casse, le middleware si. Avec `status[0]`, la valeur arrive sous forme de tableau.

**Correctif.** Comparer sur `ctx.path.toLowerCase()`. Refuser tout `status` qui n'est pas la chaîne `published` (tableau compris) sans le secret d'aperçu. Comparer le secret avec `crypto.timingSafeEqual`.

### 2. Une réponse vide de Gestmax supprime toutes les offres — vérifié dans le code

`cms/src/utils/gestmax.ts:155` lit `json.data ?? []`. Un `200` sans données passe donc comme une liste vide, et `cms/src/api/offre/services/offre.ts:71-76` supprime toutes les offres existantes. Conséquences : le site est reconstruit sans offres, Google reçoit des 404, et les réglages « à la une » et « masquée » sont perdus.

Déclencheurs possibles : mauvais paramètre `frontOffice`, droits de `rest_user` modifiés, maintenance, JSON d'une autre forme.

**Correctif.** Refuser la mise à jour si 0 offre est reçue, ou si la baisse dépasse un seuil (par exemple 50 %) alors que des offres existent. Vérifier `Array.isArray(json.data)`. Prévoir un mode « forcer » dans le BO.

Autres défauts de la synchronisation (lecture seule) :

- **Pagination tronquée** (`gestmax.ts:157`). La boucle s'arrête dès qu'un lot est plus court que `pageItems`. Si l'instance plafonne `pageItems`, seule la première page est importée et le reste est supprimé. Le tri sur `vacancy_activation_date` n'est pas stable : une offre publiée pendant la lecture décale les pages, d'où une offre manquante ou lue deux fois. Dans ce dernier cas, la contrainte d'unicité casse la synchronisation. Le plafond de 100 pages tronque aussi en silence.
- **Échec en cours de boucle non signalé** (`offre.ts:30-36`). Seul l'appel à Gestmax est dans le `try`. Un `create` ou `update` qui échoue (unicité, chaîne de plus de 255 caractères dans un `varchar(255)`) laisse le statut à « ok », sans e-mail, et bloque la synchronisation toutes les 30 minutes sur la même offre.
- **Pas de verrou** entre cron, démarrage, bouton du BO et `POST /api/offres/synchroniser` : deux synchronisations simultanées créent des doublons.
- **Rattachement à l'annuaire jamais mis à jour** : l'empreinte n'inclut pas l'entreprise.
- **Offres expirées encore servies** quand Gestmax est en panne plusieurs jours : aucun filtre sur `dateFinPublication` côté site.

### 3. Aucun contrôle de rôle sur les routes `/espace/*` — vérifié dans le code

`cms/src/api/espace/routes-admin.ts:5` n'exige que `admin::isAuthenticatedAdmin`. Seul `equipe.ts` contrôle le rôle. Les permissions dans `app.tsx` ne font que masquer les entrées de menu.

N'importe quel compte du BO (Auteur, Rédacteur) peut appeler directement :

- l'export des inscrits (`suivi.ts:99`, `:161`) : données personnelles ;
- l'envoi d'un e-mail à tous les inscrits (`suivi.ts:129`) ;
- `PUT /espace/site-carriere` (`site-carriere.ts:237`) : changer `gestmaxUrlFront` et les liens candidats redirige « Postuler » et « Espace candidat » vers un autre site ;
- `PUT /espace/apparence`, `import-entreprises` (publie immédiatement), régénération du site.

**Correctif.** Une policy `admin::hasPermissions` par route, avec l'action du gestionnaire de contenu sur le type concerné (par exemple `explorer.update` sur `parametres`, `explorer.read` sur `inscription`).

Aggravant : `site-carriere.ts:214-216, 292, 317` fait des `fetch` sur des URL saisies dans le BO (redirections suivies, corps lu sans limite, code de réponse affiché). Combiné à ce point, n'importe quel compte peut sonder le réseau interne (builder:4000, mariadb, 169.254.169.254). **Correctif :** HTTPS uniquement, refuser les IP privées, `redirect: 'manual'`, limiter la taille.

### 4. Aucune configuration de production — lecture seule

- `cms/Dockerfile:14` lance `npm run develop`, `docker-compose.yml` monte `./cms:/opt/app`, `NODE_ENV` n'est pas défini. En production, le constructeur de types reste actif : un super-admin peut modifier un type, Strapi réécrit `schema.json` sur le volume, et le prochain lancement de `generer-types.mjs` écrase la modification.
- `SEED_DEMO=true` par défaut dans `.env.example`, avec un super-admin `admin@myjobcommunity.local` au mot de passe `change_me`. `comptes-demo.ts:10-31` n'a pas de contrôle « base vide » : un compte supprimé est recréé à chaque redémarrage.
- L'aperçu des brouillons dépend du serveur de développement Astro (port 4321), ce que la documentation reconnaît (§12).
- Aucune sauvegarde (MariaDB, `uploads`), aucun script de création d'un nouveau client, `database/migrations` vide.
- Le limiteur de débit des inscriptions (`utils/limiteur.ts`, `config/server.ts` sans `proxy`) verra l'IP du reverse proxy pour tout le monde : 8 inscriptions par 10 minutes pour tout le site. Avec `proxy: true` sans limite, `X-Forwarded-For` devient falsifiable. Le limiteur est aussi en mémoire.
- Pas de CSP, de `X-Frame-Options`/`frame-ancestors` ni de HSTS dans Nginx (`web/default.conf.template`).

**Correctif.** Dockerfile en plusieurs étapes (`npm ci`, `strapi build`, `NODE_ENV=production strapi start`), compose de production sans montage du code, `SEED_DEMO=false` par défaut, refus de démarrer si un secret vaut `change_me`.

### 5. Faille XSS possible par le JSON-LD — vérifié dans le code

`site/src/components/Seo.astro:45` et `site/src/components/FilAriane.astro:40` injectent `JSON.stringify(...)` avec `set:html`. Cette fonction n'échappe pas `</script>`. Un titre d'offre, un nom d'entreprise ou un salaire saisi par un recruteur dans Gestmax et contenant `</script><script>…` s'exécute sur le site. Gestmax encode peut-être déjà ces champs : à valider.

**Correctif.** `.replace(/</g, '\\u003c')` sur la chaîne JSON.

### 6. Liens `javascript:` acceptés — lecture seule

Ni le schéma, ni `resoudreLien`, ni les composants ne filtrent le protocole sur : `siteWeb`, `inscriptionExterneUrl`, `reseau.url`, `gestmaxUrlFront`, l'option « Autre adresse » de `LienInput.tsx`, les liens de menus (`site/src/lib/liens.ts:6`) et `application_link` venu de Gestmax (`gestmax.ts:114`, `offres/[slug].astro:100,151`). Un compte du BO peut ainsi poser un XSS stocké, jusque dans l'habillage repris par Gestmax. L'import CSV, lui, valide bien ses URL.

**Correctif.** Réutiliser la liste blanche `URL_AUTORISEE` de `site/src/lib/blocks.ts` (`http:`, `https:`, `mailto:`, `tel:`) et ajouter une `regex` dans le générateur de schémas.

## 4. Accessibilité (RGAA)

**Points forts.** Liens d'évitement, `lang="fr"`, repères avec libellés, titre « Page | Site », h1 unique. Menu en « disclosure » (`aria-expanded`, `aria-controls`) utilisable au clavier et sans JavaScript. Fil d'Ariane avec `aria-current`. Formulaire d'inscription exemplaire : libellés, `autocomplete`, aide au format, récapitulatif d'erreurs focalisé, `aria-invalid`/`aria-describedby`, piège anti-robots hors du parcours clavier. Région `aria-live` et focus déplacé après « Afficher plus ». Icônes en `aria-hidden`, FAQ en `<details>`, iframes titrées. Contraste contrôlé à la saisie dans le BO.

## 5. SEO et fonctionnement du site public

- **Pagination des actualités cassée en page 1 — vérifié dans le code.** `Pagination.astro:10` utilise `page.url.first`, qu'Astro renvoie `undefined` sur la première page (`paginate.js` : `first = pageNum === 1 ? undefined : …`). Les liens numérotés deviennent `undefined/2` (404) dès 13 articles. Seul « Page suivante » fonctionne. **Correctif :** prendre `page.url.current` comme base quand `currentPage === 1`.
- **Sitemap** (`astro.config.mjs:10-16`) : l'exclusion `noIndex` ne couvre que les Pages (100 au plus). Articles, événements et entreprises marqués `noIndex` y restent. Une erreur Strapi est ignorée sans bruit. Pas de `lastmod` (`updatedAt` serait disponible).
- **Sans JavaScript**, `GET /offres?q=…` renvoie la page statique non filtrée, et le bouton « Afficher plus » reste visible sans effet (`offres/index.astro:29-101`). **Correctif :** bouton `hidden` révélé par le script, message explicite, ou pagination statique `/offres/page/N`.
- **Recherche autour d'une ville** limitée à 100 offres, avec troncature silencieuse après tri par date : le total affiché est faux et les offres les plus proches peuvent manquer (`offres/index.astro:226`). Le rayon non borné (`rayon=abc`) provoque une erreur 400.
- **Données `JobPosting`** :
  - Les champs `*_date_full` ne sont pas demandés (`gestmax.ts:41`). Si l'API ne renvoie que les champs demandés, les dates françaises sont lues à 00:00 UTC (`:63`) : `validThrough` tombe à 01:00 heure de Paris le dernier jour. Le mock contient les `_full` et masque le problème. **À valider.**
  - `datePosted` est facultatif dans le code alors qu'il est obligatoire pour Google.
  - `employmentType` dépend d'une correspondance exacte des libellés : « CDI - Temps plein » n'est pas reconnu.
  - Pas de `baseSalary` (le salaire est un texte libre).
  - `sameAs` pointe vers la fiche du site au lieu de `siteWeb`.
- **Slug dérivé du titre** : un titre modifié dans Gestmax change l'URL, sans redirection.
- **404** : l'URL canonique `/404/` est posée alors que la page est `noindex` (`Seo.astro:81`).
- **`.ics`** servi en `application/octet-stream` (le `mime.types` de Nginx ne connaît pas `ics`), lignes non repliées à 75 octets (RFC 5545).
- **Slugs réservés non protégés** : une page nommée `offres`, `evenements`, `header-footer` ou `apercu` entre en collision avec les routes Astro et reste invisible.
- **Comportement si Strapi est indisponible : bon.** Le build échoue bruyamment (`strapi.ts:25`), le builder garde la version en ligne. Réserve : une réponse `200` sans offres (cf. §3, point 2) publierait un site sans offres.

**Écarts avec l'argument commercial.**

- **Images du texte riche, logo, favicon et `og:image`** pointent vers l'original Strapi (`lib/blocks.ts:178-182`) : pas de WebP, de redimensionnement ni de `srcset`, et servies par Strapi à l'exécution. Le logo du site est chargé depuis `http://localhost:1337/uploads/…` ([Entete.astro:19](../site/src/components/Entete.astro)) : le site dépend de Strapi pour son propre logo. **Correctif :** `getImage()` au build.
- **Logos des offres** chargés depuis le domaine Gestmax (tiers).
- **Appels réseau par recherche** : 1 requête plus une par type de contrat (`offres/index.astro:243-250`). Chaque carte d'événement fait son propre appel pour les places (`CarteEvenement.astro:43`).
- **Géocodage IGN** : appel à un tiers, alors que la documentation annonce « aucun tiers ».
- **Héros** : l'image principale de 397 Ko est servie en 1600 px ; un 1024 px suffirait pour la majorité des écrans.

### Strapi ou Laravel ?

- **Côté données et API**, Strapi est bien exploité (middlewares de documents, cron, store, médias, rôles, brouillons, webhooks, aperçu). Le site Astro ne dépend que de `site/src/lib/strapi.ts` : un changement de back-office resterait local.
- **Côté interface**, le code lutte contre Strapi : environ 3 000 lignes de React, retouches CSS dépendantes de la structure HTML, racines React hors de l'arbre, et une API `/espace` parallèle qui contourne le système de droits (§3, point 3). On reconstruit un BO « façon WordPress » par-dessus Strapi.

**Recommandation.** Garder Strapi pour Laval. Figer les personnalisations du BO, ajouter des tests de bout en bout, budgéter chaque montée de version. Si l'interface sur mesure continue de grossir, Laravel avec Filament redeviendrait plus naturel pour ces écrans, au prix de refaire médias, droits et brouillons.

## 8. Ce qui est solide (vérifié)

- `GET /api/inscriptions` et `/:id` répondent 403. `populate[inscriptions]` est retiré, un filtre sur `inscriptions` est refusé (400). `emailNotificationInscriptions` est privé. `/api/users` et `/api/upload/files` répondent 403. `/api/offres/synchroniser` répond 403 en public. `/espace/*` répond 401 sans session.
- Inscription : champs en liste blanche, `statut` fixé côté serveur, champ piège, longueurs bornées, jeton d'annulation de 192 bits (`randomBytes`) en champ privé, annulation par POST explicite avec limitation de débit. La redirection 303 n'est pas une redirection ouverte (origine en liste blanche, sinon `SITE_URL`).
- Offres : requêtes construites avec `URLSearchParams` (pas d'injection dans les filtres Strapi), descriptions Gestmax passées par `sanitize-html`, `garde-offres` appliquée au service documents, `reglerOffre` n'accepte que `aLaUne` et `masquee`.
- `equipe.ts` : super-admin protégé, auto-modification interdite, rôles attribuables en liste blanche.
- Purge RGPD correcte (`taches.ts:73-84`) : événements de plus de 12 mois et inscriptions orphelines.
- Builder : bascule atomique d'un lien `current`, 3 versions conservées, nouvelle tentative après échec, la version en ligne est conservée si le build échoue.
- `.env` non versionné.

## 9. À valider sur une vraie instance Gestmax

- Valeur maximale de `pageItems`, présence et nom du champ `count`, stabilité du tri.
- Comportement de l'API quand les droits sont insuffisants : liste vide en 200, ou erreur 403 ? C'est le scénario du §3, point 2.
- Retour effectif des champs `*_date_full` et fuseau horaire des dates.
- Libellés réels des contrats (`employmentType`) et noms des champs `vac_*`.
- Encodage HTML des titres et noms d'entreprise (lié au §3, point 5).
- Longueur des URL de logo et de candidature (limite de 255 caractères en MariaDB).
- Format des messages `smartIframe` (objet ou chaîne) avec `smartIframe.enabled` actif, et en-têtes `X-Frame-Options` / `frame-ancestors` qui autorisent l'intégration.
- Intégration du plugin `HeaderFooterWp` dans le code principal de Gestmax, et présence de l'identifiant `#contenu` sur les pages Gestmax.
